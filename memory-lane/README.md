# MEMORY LANE ／ Ver.0.1 叩き台

「忘れたくない」は、あとから来る。だから、今を残す。

未来の自分が見たくなる瞬間に、今の自分が気づくためのサービス。
撮った写真を整理するのではなく、**撮らなかったはずの瞬間を生み出す**。

## ファイル

| ファイル | 内容 |
| --- | --- |
| `index.html` | トップ。3つのプロトタイプへの入口 |
| `app.html` | **ユーザー体験プロトタイプ**（12画面）。QRを読む→Mission→撮影→共有Memory→AI編集→Movie到着→未来の通知 |
| `biz.html` | **BtoB管理画面プロトタイプ**。ダッシュボード／Memory一覧／Mission設定／QR発行・POP／成果レポート／プラン／同意設定 |
| `doc.html` | **構想書・仕様書**。①画面遷移 ②Mission 50個 ③MVP機能一覧 ④BtoB管理画面 ⑤収益モデル ＋ 技術構成・KPI・法務・開発ステップ・未決定論点 |
| `missions.js` | Mission マスタ 50件。`app.html` / `biz.html` / `doc.html` が共有する唯一のデータ実体 |

依存は同梱の `../vendor/qrcode.min.js` のみ。ビルド不要、ブラウザで直接開けます。

## 見かた

1. `index.html` を開く
2. `app.html` の QR をタップして、右の「① 画面遷移」から各ステップに飛べる
3. `doc.html` に、開発会社へ渡す粒度の仕様をまとめてある

## 前提として置いた設計判断

- 参加にアプリのインストールを必須にしない（Web／PWA 優先）
- Mission は時刻もポーズも指定しない。スキップ可・期限なし
- 「撮った枚数ランキング」は出さない（競争にすると自然さが消える）
- 顔認識による人物紐付けは MVP に入れない
- 店舗に画像そのものを渡さない。集計値のみ
- 生成 AI で映像を作らない（実在の記憶に嘘を混ぜない）

## 次に決めること

`doc.html` の「11 未決定の論点」を参照。特に:

1. Memory の単位（旅行1回 or 店舗1来店 → おそらく親子の入れ子）
2. 誰が Memory を作るか（幹事 or 店舗）
3. Full Memory Movie の価格（¥1,800 は根拠のない置き数字）
4. 保存年数の約束（10年後通知を謳う以上、事業継続とセット）
5. アプリか Web か（参加率 vs 撮影体験・通知）
