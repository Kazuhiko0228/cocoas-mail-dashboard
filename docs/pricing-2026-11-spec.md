## 決定4点（安田さん 2026-11-28）
1. **機能の振り分け**
   - ベースに含める：毎日の記録・保育記録・連絡と配信・未来WA・**Miralink SI**（計画の下書き・相談・紙の読み取り・メモ→下書き・活動の3案など SI すべて）・保護者への請求書と保育料のカード払い・写真販売・登降園・**新規顧客管理**（今の Pro の機能）。
   - オプション（鍵の名前は固定）：
     - `mfile` … Miralink File（園の Miralink File の画面＝page `guide`、保護者の未来WA の Miralink File と SI `/parent/mfile/ask`）
     - `audit` … 監査書類の自動整備（監査対応・書類作成・提出書類ナビ＝page `audit` `docgen` `reqnav` と、その中の SI の書類作成 docflow）
     - `accounting` … 売上・支出管理（page `revenue`（売上管理）と `expense`（経費精算））。**保護者への請求書づくり（`billing`）はベース**
2. **今動いている園**：すべて `plan='base'`・`options=['mfile','audit','accounting']` に移す。今見えている画面は消さない。金額の上書き（monthly_yen）・割引（campaign / free_forever）などは今のまま残す（COCOAS は1園目無料のまま）。
3. **一括払い**：申込で選べて、料金の表示も出す。**自動の請求はしない**。選んだことは申込と契約の控え（`contracts.lump`）に残し、運営が今ある「まとめて請求」（subsidy.js の prepay・kind='prepay'）で手で作る。運営画面の園の詳細に「一括払いを選んだ園です（◯◯プラン・金額）」と出す。
4. **支払い方法**：「クレジット」と「口座振替」。口座振替はまだ仕組みが無いので、申込では「口座振替（準備中。それまでは請求書払い〈銀行振込〉でお受けします）」と出し、今の請求書払いで受ける（申込で選ぶと今と同じく invoice で登録）。

## 保存の形（サーバ）
- `contracts.plan`：新しい値は `'base'` だけ。古い値（connect/standard/pro/business）は移行で `'base'` に変える。受け付けるのも `'base'` だけ（古い値は 400）。
- `contracts.options TEXT[] NOT NULL DEFAULT '{}'`（値は `mfile` `audit` `accounting` のどれか・重複なし）。
- `contracts.lump TEXT`（null＝毎月払い。`y1` `y1_first5` `y2` `y2_first5`）。
- `seat_included` `seat_unit_yen` はもう使わない（列は残す。計算に使わない）。
- `platform_settings.contract_defaults`：`initial_fee`（既定 49,800・全園）。古い `initial_fee_pro` は読んだら `initial_fee` として扱う。
- 月の計算（admin.js `quote`）：明細は「ベースプラン 9,800」＋オプションごとの行（Miralink File 2,200 など）。日割り・キャンペーン・free_forever は今の仕組みのまま全体に掛ける。`monthly_yen` があればベースの額をその値に置き換える。
- `GET /admin/plans` → `{ plans: { base: {...} }, options: { mfile:{name,monthly}, audit:{...}, accounting:{...} }, lump: { y1:{name,yen,months,note}, ... }, initialFee: 49800, tax }`。
- `PUT /admin/tenants/:id/contract` は `options`（配列）と `lump` を受ける。
- ログインの応答（園の職員）：今の `plan` に加えて `options`（配列）を返す。
- 申込（`applications.payload`）：`plan:'base'`, `options:[...]`, `lump:'monthly'|'y1'|...`, 支払い方法 `pay:'card'|'transfer'`（transfer は請求書払いとして登録）。園を開くとき（onboard.js）に options と lump を契約へ写す。初期設定料は 49,800。
- **SI の線**：`/ai/*`（plan・chat・ask・scan-read・memo-draft・selftest・status）と reqnav の SI は、プランで断らない（ベースに含む）。
- **オプションの線（サーバで必ず断る）**：
  - `mfile` が無い園：`PARENT_READ.mfile` は `{docs:[]}`、`/parent/mfile/ask` は 403 `code:'plan'`（保護者の画面はこの code で枠を隠す作りのまま）、`/parent/files` で mfile の原本は開かない。職員の `PUT /state` の `mfile` は断る（403 か skipped）。
  - `audit` が無い園：docflow（`/docflow` 一式）は 403 `code:'option'`。
  - `accounting` が無い園：売上管理・経費精算のサーバの口があればそこも 403 `code:'option'`（無ければ画面で隠すだけ）。
  - 断る文：「この機能は、ご契約のオプション（◯◯）に含まれていません。」
- 契約書（contracts.js）：プラン名の文を「ベースプラン（月額 9,800円・税別）」と、契約したオプションの名前と額の一覧に。園児数による加算の条は外す。Business の文は外す。初期設定料はすべての園に 49,800円。一括払いを選んだ園は、その額と期間の条を足す。料金表（planRows）も新しい表に。`agree.js` の重要な条件の言い方も合わせる。
- 広告の出し分け（ads.js）のプランの指定は、`base` だけの一覧に（古い値の広告はそのまま全園扱いでよい）。

## 画面
- **index.html（園）**：
  - プランの札（上の帯の STANDARD など）は外す。
  - `EG_OPTS_ON=true` にし、`EG_OPTS` を `mfile` `audit` `accounting` の3つに（名前・中に入る画面は上の表）。プランで隠していた SI・新規顧客管理は誰にでも出す。
  - オプションが無い画面は、サイドバー・メニューに出さず、開こうとしたら「この機能は、ご契約のオプション（◯◯）に含まれていません。」。設定の「オプション機能」の枠に、契約中のオプションと入っていないオプション（お問い合わせへの案内）を出す。
  - 「Standard プラン以上」の文言は全部直す（EN_DICT も）。
- **parent.html**：変更なし（`code:'plan'` で枠を隠す作りのまま）。
- **admin.html（運営）**：
  - 契約の欄：プランの選択はやめ「ベースプラン」固定、オプション3つのチェック、一括払いの選択（毎月払い・4つ）、ベースの月額の上書き、初期設定料、キャンペーン・最低期間・無料はそのまま。園児数の欄は外す。
  - 見積の窓・料金・税の頁・申込の内容の表示・商談からの申込の入力・導入のウィザードの条件の段も同じ形に。「初期費用はいただきません」などの古い文は直す。
- **apply.html（申込）**：プランの選択をやめ、ベースプラン（含まれるもの）＋オプション3つのチェック、支払い方法（クレジット／口座振替〈準備中〉）、お支払いの回数（毎月／一括払い4つ）、データ移行の案内（30人まで無料・30人超は30人ごとに 10,000円・独自加工は別見積もり）。見積の計算（税込）も新しい形に（税率はサーバの値が無ければ 10%）。
- **hp.html / lp.html**：プラン3つの料金の枠と比較表を、ベースプラン＋オプション3つの形に（金額は今の判断どおり「お見積り」のまま出さない）。lp の FAQ のプラン・Business の文を直す。
- **tokushoho.html（特商法）**：販売価格を新しい表に（ベース・初期設定料・オプション3つ・一括払い4つ・データ移行。税込も併記）。最低契約期間の文は「すべてのご契約に」に。
- 英語（EN_DICT）・運営マニュアル・SI の使い方（howto-ops.json / howto-school.json）も同じ便で直す（運営マニュアルは Claude が直す）。
